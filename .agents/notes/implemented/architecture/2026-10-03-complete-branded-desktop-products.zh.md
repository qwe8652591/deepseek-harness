# Agent Note: 完整品牌 Desktop 产品

Status: implemented

[English](2026-10-03-complete-branded-desktop-products.md) | 中文

## Problem

应用安装包和独立升级的业务插件可能包含未经共同测试的不同版本。仅在启动时选择主题，不能隔离原生应用身份、本地账号存储或发行更新。

## Decision

产品构建清单将单一品牌 profile 与哈希固定的插件归档、原生图标，以及 GitHub 仓库或[自建发布目录](2026-10-16-self-hosted-product-releases.zh.md)中的通道绑定。安装包内置完整运行时及最终管理策略。Profile 从打包模块解析依赖，不复制到账号目录，也不建立指向 ASAR 内部的链接。可修改的平台源地址选择独立凭据目录；安装身份和更新地址不属于平台设置。

版本发布存放不可变二进制文件。独立品牌通道发布存放指向这些文件的各目标元数据。发布前验证签名构建完成记录和校验值，先上传文件，再推进元数据。发布要求干净检出。[产品发行文档](../../../../apps/desktop/aiko/products/README.zh.md)维护操作步骤。

Windows 产品共用 Host 的长路径解压与暂存目录替换适配器，并提供各自的 NSIS 界面。完整插件依赖超过传统 Windows 复制路径长度限制。默认复制步骤可能将这类失败误报为无法关闭应用，或在静默安装时遗漏文件。两个品牌的原生安装验证均覆盖长依赖路径、覆盖安装和卸载。

Desktop 登录流程在平台配置与登录窗口之间异步切换时保持 Electron 运行，直到主界面接管窗口关闭行为。主动取消仍然退出。验证执行真实启动入口，不由测试自行监听最后一个窗口关闭事件，以免掩盖登录窗口切换时的提前退出。

产品运行时清单是 Host 的安装解析起点。CLI 包的依赖图不包含产品 bundle 的入口包，即使其文件和间接依赖插件已安装在旁边，使用该起点仍会导致部分插件无法启用。产品 Host 使用操作系统分配的回环端口，避免不同品牌和开发实例争用同一个监听端口。打包 Host 验证读取安装中的产品元数据，检查客户端资源，并独立于登录窗口测试覆盖并发配置和重启。

## Alternatives considered

知识库授权只在 Host 验证凭据且 Client 保存配置后请求原生窗口激活。现有轮询交换仍是授权结果的依据；服务端页面关闭不能证明 Desktop 已保存连接。可信主框架 IPC 唤起发起授权的客户端，不执行导航，也不传递品牌回调地址。失败或取消的请求不会唤起窗口，原生聚焦失败不影响已保存的凭据。纯浏览器 Host 跳过这项可选操作。

整包更新限制包的变更，不限制查看和启停。禁用 Plugin Manager 会移除工作台设置依赖的 Remote 接口及侧栏入口。整包覆盖配置保留服务，在插件页展示应用提供的 bundle。它最初拒绝一切安装和卸载；[应用中心插件包](2026-10-13-app-center-packages-in-complete-products.zh.md)现在接受安装包未自带的包的本地插件包文件。安装包验证覆盖清单 RPC；使用 `--ui` 时，还在隔离渲染器中验证菜单导航、组件详情、知识库配置及模块关闭和开启。

逐个升级插件保留独立交付能力，但会使整套应用验证失效。GitHub 仓库级最新发布无法区分两个品牌和三种架构。开发环境外部目录链接不能用于打包后的 ASAR 资源内部。

## Consequences

用户只更新一个应用。各品牌产品拥有独立原生身份和数据目录。发布每个受支持目标需要更多构建时间和签名凭据。切换平台保留旧账号目录，同时不共享凭据。本地未签名验证不代表已安装签名版本的升级行为得到验证。
