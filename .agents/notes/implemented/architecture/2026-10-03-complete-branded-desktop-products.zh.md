# Agent Note: 完整品牌 Desktop 产品

Status: implemented

[English](2026-10-03-complete-branded-desktop-products.md) | 中文

## Problem

应用安装包和独立升级的业务插件可能包含未经共同测试的不同版本。仅在启动时选择主题，不能隔离原生应用身份、本地账号存储或发行更新。

## Decision

产品构建清单将单一品牌 profile 与哈希固定的插件归档、原生图标及 GitHub 仓库和通道绑定。安装包内置完整运行时及最终管理策略。Profile 从打包模块解析依赖，不复制到账号目录，也不建立指向 ASAR 内部的链接。可修改的平台源地址选择独立凭据目录；安装身份和更新地址不属于平台设置。

版本发布存放不可变二进制文件。独立品牌通道发布存放指向这些文件的各目标元数据。发布前验证签名构建完成记录和校验值，先上传文件，再推进元数据。发布要求干净检出。[产品发行文档](../../../../apps/desktop/aiko/products/README.zh.md)维护操作步骤。

Windows 产品共用 Host 的长路径解压与暂存目录替换适配器，并提供各自的 NSIS 界面。完整插件依赖超过传统 Windows 复制路径长度限制。默认复制步骤可能将这类失败误报为无法关闭应用，或在静默安装时遗漏文件。两个品牌的原生安装验证均覆盖长依赖路径、覆盖安装和卸载。

## Alternatives considered

逐个升级插件保留独立交付能力，但会使整套应用验证失效。GitHub 仓库级最新发布无法区分两个品牌和三种架构。开发环境外部目录链接不能用于打包后的 ASAR 资源内部。

## Consequences

用户只更新一个应用。各品牌产品拥有独立原生身份和数据目录。发布每个受支持目标需要更多构建时间和签名凭据。切换平台保留旧账号目录，同时不共享凭据。本地未签名验证不代表已安装签名版本的升级行为得到验证。
