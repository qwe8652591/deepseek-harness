# Agent Note: 原生用户文本中的资源引用

Status: implemented

[English](2026-09-15-resource-mention-display.md) | 中文

## Problem

普通 `@name` 展示投影把规范资源 URI 当成路径，在用户气泡中显示末尾标识和版本，而不是显示名称。将引用正文追加到该气泡还会把大量序列化数据呈现为用户输入。

## Decision

共享基础组件 `projectUserText` 在原生会话引用之外识别 `@[label](dsh-resource://...)`。两者均使用作者提供的名称；原始 URI 和版本保留在悬停标题和输入记录中。资源提供者负责 URI 校验、授权和读取。基础组件不引入特定提供者依赖或导航行为。

资源提供者把引用正文单独记录为标准插件上下文消息。原生对话分类和默认折叠的上下文行负责展示，无需额外的聊天渲染器。仅读取直接用户消息的引擎适配器必须显式接收对应资源提供者的上下文。

## Alternatives considered

**工作台自有的气泡渲染器**重复原生对话渲染，并使排队消息行的展示不一致。共享投影覆盖这两处使用者。

**从输入记录中剥离 URI 版本或隐藏文本**会丢失引用身份或模型输入依据。展示投影保留原文，上下文仍独立记录。

## Consequences

已发送和排队中的引用显示简洁名称，用户提供的名称不执行标记代码。基础组件把资源视为通用文件引用，不推断提供者专属图标。已有用户消息正文不改写，也不按标记字符串过滤。聚焦的投影快照覆盖版本、空格、标点及惰性标记文本；原生聊天测试验证独立上下文默认折叠且可展开。
