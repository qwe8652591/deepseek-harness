# Agent Note: Package-owned plugin metadata and desktop compatibility

Status: implemented

[English](2026-09-13-package-owned-plugin-metadata.md) | 中文

## 问题

目录重复保存插件版本和说明，会使每次插件升级都需要第二次发布。桌面 profile 在仓库删除后仍保留 GitHub 制品 URL；解析其他依赖时也可能再次请求这些 URL 并返回 404。组件 peer 声明无法表达应用支持的发行版本区间。

## 决策

Aiko 目录 schema 2 仅包含 npm 包名。各插件在 `dsh.market` 中发布展示资源，在 `dsh.compatibility.host` 中声明 semver 宿主版本要求；`dsh.compatibility.plugins` 声明所需插件包及其版本范围。市场读取各包的 npm 描述文件，并独立于目录发布重新验证。元数据读取失败会禁用受影响的包，同时保留其他条目。中英文 Markdown 和内嵌位图预览不需要下载运行时归档。该决定替代 [npm 目录决策](2026-09-12-aiko-npm-catalog-content.zh.md)中的内容归属。

[桌面管理器](../../../../apps/desktop/src/market-project.ts)在激活前，根据精确应用发行版本和已安装插件版本校验 staging 中的声明。市场通过隔离的 preload bridge 获取应用版本并阻止不兼容的提案。未声明范围的旧插件仍属于未验证状态；启动成功不证明所有功能兼容。对使用同一版本号的不同定制构建，semver 要求无法加以区分。

管理器在依赖解析前一起修复四个已退役的 Aiko GitHub 制品来源。旧 `dshmarket` 身份迁往 `aiko-dsh-market`；已通过官方 npm 安装但低于 schema-2 基线的市场也会升级到该基线。采用不可变运行时的 Desktop 在已确认的依赖事务中执行该迁移；启动不安装包。其他发布者、分支发行、无关插件、会话数据和工作区保留各自身份。迁移使用 npm，可能需要联网；解析或健康检查失败会保留活跃安装。

## 考虑过的替代方案

**继续在目录保存精确版本。** 这会保留重复的发行信息归属和第二次发布步骤。

**从每个运行包读取说明。** Office 包含三个解释器；它的 npm 描述文件可以承载小得多的展示数据。

**只更改当前选中插件的来源。** pnpm 会解析周围的依赖图，仍可能请求其他已退役制品。明确限定于第一方的迁移在一个 staging 事务中覆盖所有受影响的已安装包。

**把所有 peer 不匹配都视为应用不兼容。** 组件版本独立于桌面发行版；可选 peer 和历史上的宽泛声明不足以形成可靠的应用版本区间。

## 影响

常规插件发布不需要更新目录。新增或移除允许的包仍需发布目录。兼容性强制校验和自动修复需要更新后的桌面安装器；仅更新目录无法修复旧安装器。四个 Aiko 插件最初声明精确验证过的 `0.1.5-alpha.2` 应用版本。后续版本只有在完成相应验证后才扩大范围。

由于 pnpm 只采用第一个匹配的包规则，安装器会记录每次选择的 npm 精确版本，并将其与同一包已有的精确发布时间例外合并为一条精确版本并集。标签和 HTTPS 制品不会获得豁免。安装器保留已批准的版本，拒绝版本范围和通配符。历史 `0.1.5-alpha.2` Apple Silicon 修复包复用摘要固定的 Mac 运行时和核心包集合，更新桌面外壳与 npm seed，刷新 ASAR 完整性并对内测应用进行 ad hoc 签名。原生检查覆盖离线首次启动、编辑快捷键、staging 失败后的保留行为以及启动迁移；该发行版仍未经过公证，并禁用自动更新。
