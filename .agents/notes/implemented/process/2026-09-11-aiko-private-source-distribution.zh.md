# Agent Note: Aiko 私有源码与公开分发

Status: implemented

[English](2026-09-11-aiko-private-source-distribution.md) | 中文

## 问题

Aiko 客户端通过公开的 GitHub Release URL 安装插件。限制这些 URL 的访问会破坏安装，除非为每个客户端增加鉴权。公开 Fork 还保留已发布的源码历史，而持续开发需要限制访问。

## 决策

独立的私有仓库负责客户端和插件的活跃开发。公开仓库保留已发布历史及不可变的发布制品；公开组织目录保留其分发标识和下载 URL。本地 checkout 使用私有的 `source` 推送 remote，并保留官方 upstream remote。公开运行包省略可选的 TypeScript 源码及 source map；可执行 JavaScript 和必需的 Python 仍随包分发。

[Mac 测试工作流](../../../../.github/workflows/aiko-macos-test.yml)构建选定的私有客户端提交。缓存标识包含该提交、架构及固定的公开 Office 测试版本。Office fixture 验证从已发布 tarball 安装的插件，不提供客户端实现。私有制品包含校验和及来源信息。维护者将验证通过的二进制文件发布到公开客户端仓库，不推送私有实现提交，也不向应用嵌入 GitHub 凭据。

测试应用保留独立的数据目录，且没有更新源。临时签名允许原生验证，不改变正式签名要求。工作流在两种 Mac 架构上验证 ZIP 解压、签名、首次离线启动、市场入口以及已安装 Office 的文档操作。

## 考虑过的替代方案

**将分发仓库设为私有。** 这会使匿名下载失效，也无法将已有的公开 Fork 变为独立私有仓库。

**通过 Office 仓库维护的上游补丁构建客户端。** 这会重复客户端归属，并可能遗漏私有客户端变更。因此客户端构建使用自身 checkout；公开 Office 版本只提供已发布的验证 fixture。

**原位替换已发布包。** 现有客户端和锁文件依赖其字节及校验和。更新后的制品使用新的版本；迁移分发位置时复制原有字节并保留旧 URL。

## 影响

新源码提交保持私有，用户继续匿名安装。仓库私有性不会隐藏历史公开代码或可执行插件代码。跨仓库发布仍由维护者显式执行。原生冒烟结果验证测试版本；正式 Mac 分发仍要求 Developer ID 签名和公证。
